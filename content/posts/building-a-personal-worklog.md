## 先决定它不是什么

这个网站不是一份精心包装的履历，也不追求每天更新。它更像一张长期展开的工作台：完整文章用于解释一个已经想清楚的问题，笔记保留尚未收束的观察，项目记录则回答“最近到底做了什么”。

参考 Changelog 的时间线结构，是因为它天然强调**变化**。日期、类型和标签先帮助读者定位上下文，标题与摘要再决定是否值得继续阅读。相比卡片瀑布流，这种结构更安静，也更适合持续积累。

## 内容应该比系统更容易维护

每篇文章只是一个 Markdown 文件。Frontmatter 负责描述标题、时间、类型和标签，正文仍然保持普通文本：

```yaml
title: "文章标题"
publishedAt: "2026-10-28"
type: "project"
tags:
  - Next.js
  - Markdown
```

构建时，系统会校验字段、生成文章页面，并同步更新归档、RSS 与 sitemap。这样，发布新内容的动作始终是“新增一个文件”，而不是登录后台、填写表单或维护数据库。

## 一条有意保留的边界

首版不提供评论、账号和在线编辑器。它们都可以做，但会把注意力从内容本身移到运营系统。对个人网站而言，少一个运行时服务，就少一个需要持续照看的故障点。

我希望这份手记最终呈现的不是“我知道多少”，而是“一个想法如何逐步变得清晰”。
